## 〇、30 秒看懂整条链路

*策划写 Excel → 工具生成"代码 + 数据" → 业务读表。就这三步。*

> [!TIP]
> **四行结构 + 三步 + 一行加载**
>
> ① 写 Excel（每张工作表 = 一张表）
>    第 1 行：字段名     ID | Name  | Quality
>    第 2 行：类型       int | string | int
>    第 3 行：描述       英雄ID | 英雄名 | 品质
>    第 4 行起：数据      1001 | 亚瑟 | 3
> 
> ② 启动工具 → 选 Excel → [读取] → 选三个输出目录 → [开始导出]
> 
> ③ 把产物拷进工程，业务就这么读：
> await DataTableManager.LoadAsync<HeroTable>();
> HeroTable.Instance.FindByKey(1001, out  var hero);   // 拿到 1001 这行
> 没有第 4 步。表的读写都走**资源系统**（表就是资源），所以打包、热更、分包与其它资源一套规则。

> **人话** 导表工具 = 一个独立的 WPF 小工具：吃 Excel，吐 C# 数据类 + txt 数据文件。
> 它**不需要开 Unity**、也不依赖 Excel 安装（自带 xlsx 解析）；生成的代码是纯 C#，可以直接进版本库看 diff。

## 一、准备：运行与启动

| 项 | 说明 |
|---|---|
| 运行环境 | **.NET 8 桌面运行时**（Windows）。工程目标是 `net8.0-windows` |
| 启动（开发期） | `cd RevolutionFramework\Revolution.ExcelTool` → `dotnet run` |
| 启动（给策划用） | 直接跑 `Revolution.ExcelTool\bin\Debug\net8.0-windows\Revolution.ExcelTool.exe`；给别人就用 `dotnet publish -c Release` 把产物目录拷走（零第三方依赖） |
| 首次启动 | 会自动在附近找 `RevolutionFrameWork_Unity` 并**预填三个输出目录**；没猜到就手动选一下（不影响使用） |


### 界面六个区块（从左到右、从上到下点一遍就完事）


```text
① Excel 数据源    [路径输入框]  [选择文件]  [选择目录]  [读取]
② 表列表          读到的每张工作表都在这里（点一下看右边）
③ 表结构预览      字段摘要 + 前 50 行数据（先在这里确认没读歪）
④ 输出路径        数据结构类 [目录] / 容器类 [目录] / TXT 数据文件 [目录]
⑤ [开始导出]      状态提示
⑥ 日志            每一步的结果都在这里，成功失败都看得见
```

> [!NOTE]
> **先"读取"再"导出"**

## 二、Excel 该怎么写（唯一的契约）

| 行 | 内容 | 说明 |
|---|---|---|
| 第 1 行 | **字段名** | 要能当 C# 字段名 |
| 第 2 行 | **字段类型** | 只支持 `int` / `float` / `string` / `bool` |
| 第 3 行 | **字段描述** | 只进代码注释与 txt 表头，不参与数据 |
| 第 4 行起 | **数据** | 一行一条记录 |

> [!TIP]
> **两条最容易记住的规则**
> ① 第一个字段（第一列）就是主键
> ② 一个工作表 = 一张表
> Hero
> Hero
> HeroTable


### 一个能直接抄的例子（工作表名：Hero）

|  | A | B | C | D | E | F | G | H |
|---|---|---|---|---|---|---|---|---|
| **1** | ID | Name | Quality | Attack | Hp | MoveSpeed | IsRanged | Camp |
| **2** | int | string | int | float | int | float | bool | string |
| **3** | 英雄ID | 英雄名 | 品质 | 攻击力 | 生命值 | 移动速度 | 是否远程 | 所属阵营 |
| **4** | 1001 | 亚瑟 | 3 | 120.5 | 3600 | 3.8 | false | 秩序 |
| **5** | 1002 | 妲己 | 3 | 95 | 3200 | 3.6 | true | 无序 |


### 列与行的处理规则（省得踩坑）

| 情况 | 行为 |
|---|---|
| 第 1 行该列留空 | 整列忽略（右侧常见的空列不用管） |
| 列名以 `#` 开头 | 视为策划备注列，整列忽略 |
| 某行少填了几列 | 按空值处理（列数以第 1 行为准） |
| 整行为空 | 跳过 |
| 该行第一列以 `#` 开头 | 整行当作注释跳过（表尾写备注很方便） |
| 主键列为空 / 主键重复 | **报错**（会在 ⑥ 日志里写清是哪一行） |

> [!NOTE]
> **可运行的样例**
> Revolution.Demo\ExcelTool\Excel\DemoConfig.xlsx
> string 主键

## 三、导出 → 接进 Unity

*工具只负责"生成文件"，放哪由你决定（默认会预填好）。*

| 输出 | 拷到哪 | 说明 |
|---|---|---|
| 数据结构类 + 容器类 | `Assets/Revolution/Generation/` | C# 代码，进版本库（生成物，别手改） |
| TXT 数据文件 | **资源根目录**下（如 `Assets/GameRes/Data/`） | 它**是资源**，走资源系统加载 / 打包 / 热更 |

Excel 改动 → 工具导出 → 拷贝产物 → Unity 自动导入 → 生成映射（LiteAB） → 运行期 LoadAsync 读表

> [!WARNING]
> **别漏掉"生成映射"**
> AB 模式
> 「扫描并生成映射」

## 四、业务侧：一行读表（运行时 API）

*入口是 `DataTableManager`；生成的 `XxxTable.Instance` 就是它的快捷方式。*

| 我想… | 这么写 |
|---|---|
| 加载一张表（异步，推荐） | `await DataTableManager.LoadAsync<HeroTable>()` |
| 加载（同步） | `HeroTable t = DataTableManager.Load<HeroTable>()` |
| 拿已加载的表 | `DataTableManager.Get<HeroTable>()` |
| 拿不到就算了 | `DataTableManager.TryGet<HeroTable>(out var t)` |
| 判断是否已加载 | `DataTableManager.IsLoaded<HeroTable>()` |
| 卸载 / 全部卸载 | `DataTableManager.Unload<HeroTable>()` · `UnloadAll()` |
| 看加载了哪些 | `DataTableManager.Tables` · `DataTableManager.LoadedCount` |
| 按主键查一行 | `HeroTable.Instance.FindByKey(1001, out var hero)` |

> [!TIP]
> **为什么"表 = 资源"很重要**
> 打包、分包、热更、卸载
> ResGroup.Config

## 五、新手最容易踩的 5 个坑

| 坑 | 正确做法 |
|---|---|
| ① 主键留空 / 重复 | 第一个字段必须每行都有值且唯一（工具会报错，日志里写着行号） |
| ② 用了不支持的类型（如 `double`/`long`） | 只有 `int`/`float`/`string`/`bool`；需要别的就在业务里转换 |
| ③ 改了工作表名，业务里没跟着改 | 表名 = 工作表名，生成的类名跟着变 → 改名后要重新编译（编译期就报错，不会静默） |
| ④ 改了 Excel 没重新导出 | 数据是**快照**：Excel 改动必须重导一次（工具不监听 Excel 变化） |
| ⑤ 直接改生成的 C# 文件 | 那是生成物，下次导出会被覆盖 → 要改结构就改 Excel，要改逻辑就写在业务层 |

> [!NOTE]
> **最坑的一条：忘了"生成映射"**
> 「扫描并生成映射」
