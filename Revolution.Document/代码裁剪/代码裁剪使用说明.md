# 代码裁剪 · 使用说明

> 这份文档只回答一件事：**代码裁剪要不要开、开了怎么不出事。**
> 读完你能做到：知道**主推方案是关掉**并会自己配 · 知道关掉的代价是多少、怎么自己测 · 知道真要开时框架给了哪三层护栏 · 出问题时按症状反查是谁被裁了

---

## 〇、先说结论（30 秒）

> [!IMPORTANT]
> **主推建议：直接把 Managed Stripping Level 关掉。**
> 理由很简单：**代码裁剪省的是包体，赔的是"编辑器好好地、真机突然瘸"** ——
> 而这种故障不报错、难复现、极难往裁剪上想（十个线上问题里九个想不到它）。
> 关掉裁剪的代价只有一个：包体变大 —— 而那个数字**你自己花 3 分钟就能测出来**（见第二节）。

**三个常见误解，先澄清**（很多人在这里做错决定）：

| 常见说法 | 实际情况 |
|---|---|
| "关裁剪 = 包体爆炸，不敢关" | 确实会涨，但**涨多少因项目而异**，必须自己实测（第二节给了 3 分钟方法）。拿"别人说会涨 30%"当依据是错的 |
| "开了裁剪能省一大半包体" | 对**安卓原包**帮助有限（它的体积大头是贴图/音频/模型，代码占比不高）；**只有小游戏的代码包**才真的靠它省量 |
| "我 link.xml 都写了，裁剪也没事" | 业务里的**反射、泛型、原生组件挂载**这三类，link.xml **天然覆盖不全** —— 漏一个就是一次真机故障。护栏是"降低概率"，不是"保证没事" |

---

## 一、怎么关（跟着做，3 分钟）

**第 1 步：改设置**

1. 打开 `Project Settings`（菜单 `Edit → Project Settings…`）
2. 左侧选 `Player`
3. 找到 `Other Settings` 这一节里的 **Managed Stripping Level**
4. 改成 **`Disabled`**（保守稳妥）；如果这个选项只有 `Minimal` 可选，选 `Minimal` 也能避开绝大部分问题

> 名字提示：Unity 6 上这一项的措辞改成了 `Code Stripping`、位置也挪了位，但找**写着 `Disabled` / `Minimal` 的那个下拉框**就行。
> 旁边的 `IL2CPP Code Generation`、`Incremental Il2Cpp Build` 与裁剪无关，别动。

**第 2 步：重新出包**

这是**构建期**行为 —— 改完设置必须重新出包才生效，改代码不生效。已经装在用户手机上的旧包不会因为这次修改而变化。

**第 3 步：确认一下（可选，但建议做）**

进游戏时看 Console 有没有这一行：

```text
[裁剪自检] 关键类型全部在位（已查 12 项）
```

这行是框架的 `RevStripGuard` 打的（进游戏自动跑一次）。看到它就等于**确认"物理 / UI / 动画 / 音频这些关键类型都还在"**。
真出包后主动调一次 `RevStripGuard.Check()` 也可以，返回 0 = 通过。

## 二、关掉的代价：自己测，别信别人的数字

**代价 = 包体变大**，具体多少**只能实测**（跟引擎版本、用了哪些原生模块、代码量都有关系）。

**3 分钟实测法**：

1. 保持当前设置出一次包，记下包体（安卓看 APK/AAB 的大小；小游戏看上传时的代码包大小）
2. 改成 `Disabled` 再出一次包
3. **差值就是你的真实代价** —— 用它做决策，比任何"听说要涨 30%"都准

**影响大小的几个因素**（供你预判）：

| 因素 | 说明 |
|---|---|
| 引擎版本 | 版本越新，引擎自身"可裁的部分"越多，差距越明显 |
| 用了哪些原生模块 | 物理 / 动画 / 粒子 / TMP 这些被裁掉的是"整块"，比普通 C# 代码更值钱 |
| 代码量 | 自己的业务代码只是其中一部分 |

> **权衡建议**：先按主推关掉、测出数字；只有当"关掉后的包体**确实**超了平台上限"时，再回到第四节走"精准保留"那条路 —— 那样你手里有真实数据，决策也站得住。

## 三、什么时候还是应该开（三个信号）

主推是关掉，但这三种情况下应该重新考虑：

1. **小游戏的包体已经逼近平台硬上限** —— 微信 / 抖音小游戏对首包体积有硬限制（具体数值以平台最新文档为准，平台会调整）。如果你实测发现关掉就超，那说明"关掉"这条路在你的项目里走不通。
2. **实测数据表明省下来的比例很可观**（比如省了 30% 以上且你在意）。
3. **CI 里有明确的包体红线**（超过就发版失败）。

即使走这条路，也**别回到"裸开"**：至少把框架自带的 `Assets/Revolution/link.xml` 留着（它是零成本的），并跑一次第四节说的生成工具。

## 四、真要开的话：框架给的三层护栏

这三层是**配合使用**的，不是三选一。它们的共同目标：把"被裁"这件事从"真机上的神秘故障"变成"出包时看得见的清单"。

### ① 框架 `link.xml`：固定保住 Unity 原生模块

`Assets/Revolution/link.xml` 随框架一起安装，里面固定保住了：

| 程序集 | 不保会怎样（真机症状） |
|---|---|
| `UnityEngine.PhysicsModule` | 刚体变"空壳"：`Physics.Raycast` 恒返回 false、重力/碰撞不生效 |
| `UnityEngine.Physics2DModule` | 2D 物理同样全废 |
| `UnityEngine.UIModule` | 面板全部不显示 |
| `UnityEngine.AnimationModule` | Animator 不驱动任何动画 |
| `UnityEngine.AudioModule` | 全游戏没声音 |
| `UnityEngine.ParticleSystemModule` | 粒子特效静默不播 |

**为什么原生模块这么特殊**：它们的真实现就在引擎原生侧（C++），托管层只是一层薄薄的 wrapper。Unity 的裁剪器只看"谁在代码里调用过这些 C# 类" —— 业务没直接调、但场景里挂了组件，它就把 wrapper 一起裁掉，而场景里那半边（native）还好好地在那儿。于是就成了最难查的一类故障：**不报错、只是不工作**。

### ② 菜单「生成 IL2CPP 裁剪保护」：把业务侧也保住

菜单：`Revolution.Tools/平台/生成 IL2CPP 裁剪保护 (link.xml)`

它会扫出两类东西写进 `Assets/link.xml`：

- **靠反射工作的业务类型** —— 所有 `RevUIPanel` / `RevUIPart` / `RevSingleton<T>` 的派生类
  （框架的 UI 靠 `[RevBind]` 字段反射装配、被裁了就是"面板空白 / 按钮点不动"）
- **代码里用到的 Unity 原生模块** —— NavMesh / Terrain / 粒子 / VFX / TMP / Input System 等

> 新增 / 改名面板或单例后**重新执行一次**。换 Unity 版本、加了新原生模块、改了出包配置之后，也建议重跑一次。

### ③ `RevStripGuard`：进游戏自动确认"关键类型还在吗"

进游戏（首个场景加载之前）自动跑一次，逐个问引擎"这个类型还在吗"，缺了就用 `RevLog.Error` 报出**【缺什么 + 什么症状 + 怎么修】**。

这是把"沉默的故障"变成"启动时一条明确的错误"——你不用再靠"玩法瘫了 → 怀疑裁剪 → 瞎试"这条链路。
也可以手动调 `RevStripGuard.Check()`（返回缺失数量，0 = 通过），出包后主动验一次是好习惯。

> ⚠️ 一个容易写错的地方（框架内部已经避开）：这类自检**只能用字符串去问**（`Type.GetType("...")`），
> 绝不能直接引用被检查的类型 —— 一旦直接引用，裁剪器就认为"有人用"，那个类型不会被裁，自检就会永远显示"通过"。

## 五、被裁了会是什么症状（反查表）

出真机包后出现下面的现象，先来这里对一下：

| 症状 | 多半是谁被裁了 |
|---|---|
| 刚体不下落、不碰撞、`AddForce` 没反应 | `UnityEngine.PhysicsModule` |
| `Physics.Raycast` / `OverlapSphere` 永远返回空 | `UnityEngine.PhysicsModule` |
| 2D 物理完全不工作 | `UnityEngine.Physics2DModule` |
| UI 面板空白、按钮点了没反应、动态列表不刷新 | 业务面板类型没进 `link.xml` |
| 键位全部失灵（只有一条警告） | `UnityEngine.KeyCode` 枚举 |
| 全游戏没声音 | `UnityEngine.AudioModule` |
| 动画不播放 | `UnityEngine.AnimationModule` |
| 粒子特效不冒 | `UnityEngine.ParticleSystemModule` |
| NavMesh / 寻路不工作 | `UnityEngine.AIModule` |
| TextMeshPro 文字全空 | `Unity.TextMeshPro` |

**最快的确认方式**：出包后启动时看 Console 有没有 `[裁剪自检]` 的 Error；有的话它已经把"缺什么"和"怎么修"直接打出来了。
